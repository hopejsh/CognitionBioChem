## 0. Architecture in one paragraph

The **append-only JSONL ledger under `memory/provenance/` is the single source of truth.** It is written by exactly one process per shard, never rewritten, never deleted, and diffs cleanly in git. The **SQLite database under `memory/index/` is a pure function of the ledger** — it has zero authority, is gitignored, and is rebuilt from scratch whenever any ledger file changes. There is exactly one write path (append a line to your own shard file) and exactly one read path (stat the ledger, rebuild if stale, query the index). Because the coupling is strictly unidirectional there is no synchronization problem, no lock, and no reconciliation logic. Three mechanisms are borrowed and nothing else: Zep's bi-temporal invalidate-never-delete, Voyager's verify-before-commit gate, Letta's sleep-time consolidation.

**Non-goals (explicitly out of scope, do not implement):** ANN indexes, neural embedding models, entity extraction by LLM, a server process, a network listener, cross-shard writes, in-place mutation of any ledger record.

### 1.1 `shard_id` — exact derivation

```
shard_id  = f"{agent_id}.{pid}.{boot_nonce}"
agent_id  : ^[a-z0-9][a-z0-9_-]{1,38}$        # e.g. "admet-critic", "lit-retrieval-03"
pid       : os.getpid(), decimal
boot_nonce: first 8 hex chars of blake2b(f"{socket.gethostname()}|{psutil-free boot marker}|{time.time_ns()}")
```

`boot_nonce` MUST be computed once per process at `Ledger.__init__` from
`hashlib.blake2b(f"{socket.gethostname()}|{os.getpid()}|{time.time_ns()}|{os.urandom(8).hex()}".encode(), digest_size=4).hexdigest()`.

**Rationale (risk mitigation "one writer per file"):** an agent restarted while the old process is still alive gets a different `pid`/`boot_nonce` and therefore a different file. Two live writers can never share a file. The `agent_id` remains queryable because it is both a filename component and a field inside every record.

### 1.2 Retirement of shards

Shard files are never merged or deleted. `mem stats` reports shard count. If shard count exceeds `limits.max_shards` (default 2000) `mem doctor` emits a WARN suggesting `mem export --compact` (which writes a *new* consolidated read-only archive under `provenance/_archive/` and leaves originals in place; the archive is informational and is NOT read by the builder).

## 2. The ledger: record formats

### 2.1 Serialization rules (normative, non-negotiable)

Every line MUST be produced by exactly:

```python
line = json.dumps(
    obj,
    sort_keys=True,
    ensure_ascii=False,
    allow_nan=False,
    separators=(",", ":"),
) + "\n"
data = line.encode("utf-8")
assert len(data) <= 65536
```

* Exactly one record per line. No pretty-printing. No blank lines. No trailing whitespace.
* `sort_keys=True` guarantees byte-identical output for identical content → clean line diffs.
* `allow_nan=False` — NaN/Infinity are rejected at write; a float field that would be NaN is a validation error.
* **Rewriting any line of any `provenance/*.jsonl` file is a PROHIBITED operation** with exactly one narrow exception (`mem redact --hard`, §7.5), which is gated by lock + explicit confirmation + a tombstone record.
* Corrections are new records plus `SUPERSEDES` edges. There is no `UPDATE`.

### 2.2 Common envelope

Every record in every stream carries these fields:

| field | type | notes |
|---|---|---|
| `rec` | str enum | `CLAIM`, `STATUS`, `EDGE`, `ENTITY`, `MENTION`, `RUN`, `EVENT` |
| `v` | int | ledger schema version, currently `1` |
| `id` | str | globally unique, prefixed, derived (§2.4) |
| `agent` | str | `agent_id` of the writer |
| `shard` | str | `shard_id` (redundant with filename, kept for archive safety) |
| `run_id` | str | `run_<26-char base32 ULID-like>`; see §2.5 |
| `seq` | int | 0-based monotonically increasing counter, **per stream per shard** |
| `ts_author` | str | RFC3339 UTC, microsecond precision, `Z` suffix. Agent's own clock at authoring. |
| `ts_ingest` | int | `time.time_ns()` at the moment of append. **This is the ingest/transaction time.** |

**Total order** over all records in the ledger is the tuple `(ts_ingest, shard, seq)`, ascending. This is the fold order for all state derivation. `ts_author` is never used for ordering (agent clocks are not synchronized); it is retained for reporting.

### 2.3 Stream: `claims.<shard_id>.jsonl` — `rec="CLAIM"`

```json
{"agent":"admet-critic","claim":"Compound CHEMBL25 shows hepatic CYP3A4 inhibition IC50 < 1 uM","claim_type":"ADMET","confidence":0.82,"embedding_ref":"h1:2048:9f3c...","evidence_refs":["doi:10.1021/acs.jmedchem.3c00001"],"episodic_ref":"episodic/2026/08/16/run_01K.../000012.admet-critic.trace.jsonl#L440","id":"clm_7b1f...","importance":0.7,"memory_class":"semantic","rec":"CLAIM","run_id":"run_01K...","seq":12,"shard":"admet-critic.48213.9c1a2f30","source":{"kind":"literature","ref":"PMID:38112233","locator":"Table 2"},"t_valid":"2026-08-16T00:00:00.000000Z","tags":["cyp3a4","chembl25"],"ts_author":"2026-08-16T12:34:56.123456Z","ts_ingest":1786998896123456789,"v":1}
```

| field | type | required | constraint |
|---|---|---|---|
| `claim` | str | yes | 1..8000 chars after NFKC normalize; MUST NOT be only whitespace |
| `claim_type` | str enum | yes | `ADMET`, `TARGET`, `MECHANISM`, `STRUCTURE`, `CLINICAL`, `GENETIC`, `CHEMISTRY`, `METHOD`, `DATASET`, `META`, `OTHER` |
| `source` | object | yes | `{kind, ref, locator?}`. `kind` ∈ `literature`, `database`, `computation`, `experiment`, `agent_inference`, `user`. `ref` MUST be non-empty **unless** `kind == "agent_inference"`. |
| `confidence` | float | yes | `0.0 <= c <= 1.0`. **Intra-agent ordinal only** (§5.6). |
| `importance` | float | no, default `0.5` | `0.0..1.0`, self-reported |
| `memory_class` | str enum | no, default `semantic` | `semantic`, `episodic`, `procedural`, `entity` |
| `t_valid` | str RFC3339 or null | no, default = `ts_author` | start of **valid time** |
| `t_invalid` | — | **MUST NOT appear on a CLAIM record** | valid-time end is set only via `STATUS` (§3.4) |
| `tags` | list[str] | no | each `^[a-z0-9][a-z0-9._-]{0,63}$`, ≤ 32 entries, sorted, deduplicated |
| `evidence_refs` | list[str] | no | free-form external identifiers (DOI/PMID/accession/path) |
| `episodic_ref` | str or null | no | `path#Lnnn` pointer into `memory/episodic/` |
| `embedding_ref` | str | yes (written by lib) | `h1:{D}:{blake2b16 of the doc vector bytes}` — §5.3.5 |
| `nonce` | str | no | opaque; include to force a distinct id for a deliberate re-assertion |
| `supersedes` | str or null | no | convenience; if set, the library MUST also append a `SUPERSEDES` edge and a `STATUS` record in the same call |

**Hard rejections (exit code 2):** missing required field; `claim` > 8000 chars; `source.ref` empty for a citable `kind`; unknown `claim_type`; `confidence` out of range; any float NaN; serialized line > 65536 bytes (fix: move bulk text to `episodic/` and reference it).

### 2.4 Identifier derivation (idempotency keys)

```python
def content_key(kind: str, parts: dict) -> str:
    canon = json.dumps(parts, sort_keys=True, ensure_ascii=False,
                       allow_nan=False, separators=(",", ":"))
    return hashlib.blake2b(canon.encode("utf-8"),
                           digest_size=16,
                           person=f"memid1:{kind}".encode()).hexdigest()   # 32 hex chars
```

| record | prefix | `parts` (exact) |
|---|---|---|
| CLAIM | `clm_` | `{"agent","claim_type","text_norm","source_kind","source_ref","t_valid","nonce"}` |
| STATUS | `sts_` | `{"agent","target_id","to_status","reason_norm","evidence_edge_id","t_invalid"}` |
| EDGE | `edg_` | `{"agent","src","rel","dst"}` |
| ENTITY | `ent_` | `{"kind","primary_xref"}` if any xref present, else `{"kind","slug"}` — **`agent` is deliberately excluded** so two agents naming the same entity produce the same id |
| MENTION | `mnt_` | `{"item_id","entity_id","span_start","span_end","role"}` |
| RUN | `run_` | `{"agent","pid","boot_nonce","started_ts_ns"}` |
| EVENT | `evt_` | `{"agent","shard","stream_seq","event_type","ts_ingest"}` |

`text_norm` is `normalize_text()` from §5.3.1. `id = prefix + content_key`.

**Idempotency contract:** appending a record whose `id` already exists **in the same shard** is a no-op that returns `WriteResult(deduped=True)` and appends nothing. `confidence`, `importance`, `tags`, `ts_author` are deliberately excluded from the key so that a crashed-and-retried write is idempotent. To assert the *same text* again on purpose (e.g. after new evidence), set `nonce`.

The same claim text asserted by a *different agent* yields a different id — this is intentional and correct; collapsing it is the job of `SAME_AS` (§6.3), never of the id function.

### 2.5 `run_id`

```python
run_id = "run_" + base32_crockford(int(time.time()*1000)).rjust(10,"0") + secrets.token_hex(8)
```
Lexicographically sortable by start time. 26 chars after the prefix.

### 2.6 Stream: `status.<shard_id>.jsonl` — `rec="STATUS"`

The **only** mechanism that changes a claim's status or closes its valid-time interval.

| field | type | required | constraint |
|---|---|---|---|
| `target_id` | str | yes | a `clm_...` id; MAY belong to another agent's shard |
| `to_status` | str enum | yes | `ASSERTED`, `VERIFIED`, `REFUTED`, `SUPERSEDED` |
| `from_status` | str or null | no | advisory only; **never** used for optimistic locking |
| `reason` | str | yes | 1..2000 chars |
| `evidence_edge_id` | str or null | conditional | see gate below |
| `source` | object | yes | same shape as CLAIM `source` |
| `t_invalid` | str RFC3339 or null | no | sets valid-time end of `target_id`. Required when `to_status ∈ {REFUTED, SUPERSEDED}`; defaults to `ts_author`. |
| `superseded_by` | str or null | conditional | required when `to_status == "SUPERSEDED"` |

**The Voyager gate (verify-before-commit), enforced at append time — hard reject on failure:**

```
to_status == "VERIFIED"   requires: evidence_edge_id resolves to an existing EDGE with
                                    rel ∈ {SUPPORTS, CITES}, dst == target_id,
                                    and edge.src is a CLAIM whose source.ref != ""
to_status == "REFUTED"    requires: evidence_edge_id resolves to an existing EDGE with
                                    rel == "REFUTES", dst == target_id,
                                    and edge.src is a CLAIM whose source.ref != ""
                                    and edge.src.source.kind != "agent_inference"
to_status == "SUPERSEDED" requires: an existing EDGE with rel == "SUPERSEDES",
                                    src == superseded_by, dst == target_id
to_status == "ASSERTED"   requires: nothing (used only to re-open a contested claim; must
                                    still carry a reason)
```

"Resolves to an existing EDGE" means: present in the freshly-rebuilt derived index **or** in the current process's in-flight append buffer for this run. The library's `refute()` / `verify()` / `supersede()` convenience methods write the edge first, `fsync`, then the status, so the gate is always satisfiable in one call.

### 2.7 Stream: `edges.<shard_id>.jsonl` — `rec="EDGE"`

| field | type | constraint |
|---|---|---|
| `src` | str | id of a CLAIM or ENTITY |
| `rel` | str enum | `REFUTES`, `SUPPORTS`, `CITES`, `SUPERSEDES`, `SAME_AS`, `DERIVES_FROM` |
| `dst` | str | id of a CLAIM, ENTITY, or an external ref token (`doi:...`, `PMID:...`) |
| `note` | str | 0..1000 chars |
| `weight` | float | `0.0..1.0`, default `1.0`; advisory strength |

`SAME_AS` MUST be treated as symmetric by readers; writers emit it once in either direction. All other relations are directed. Self-edges (`src == dst`) are rejected.

### 2.8 Stream: `entities.<shard_id>.jsonl` — `rec="ENTITY"`

| field | type | constraint |
|---|---|---|
| `kind` | str enum | `GENE`, `PROTEIN`, `COMPOUND`, `TARGET`, `DISEASE`, `PATHWAY`, `ASSAY`, `DATASET`, `PAPER`, `ORGANISM`, `METRIC`, `OTHER` |
| `canonical_name` | str | 1..300 chars |
| `slug` | str | `^[a-z0-9][a-z0-9-]{0,79}$`, derived: NFKD → ASCII → lowercase → non-alnum to `-` → collapse → trim |
| `xrefs` | object | `{db: id}`, db ∈ `CHEMBL`,`UNIPROT`,`ENSEMBL`,`HGNC`,`PUBCHEM`,`MONDO`,`DOID`,`GO`,`REACTOME`,`PDB`,`NCT`,`DOI`,`PMID`. Keys sorted by `sort_keys`. |
| `aliases` | list[str] | ≤ 32 |

`primary_xref` for id derivation = `f"{db}:{id}"` for the lexicographically first `db` present in `xrefs`. **This is deterministic cross-agent entity resolution with no model and no LLM.** Two agents that both attach `CHEMBL:CHEMBL25` produce the identical `ent_` id and the rows unify in the index. Name-only entities fall back to `slug` and are reconciled later by `SAME_AS` from consolidation (§6.3).

### 2.9 Stream: `mentions.<shard_id>.jsonl` — `rec="MENTION"`

| field | type | constraint |
|---|---|---|
| `item_id` | str | a `clm_` id |
| `entity_id` | str | an `ent_` id |
| `span_start`,`span_end` | int | byte offsets into the *normalized* claim text; `0 <= start < end <= len` |
| `surface` | str | the literal substring |
| `role` | str enum | `SUBJECT`, `OBJECT`, `CONTEXT`, `MEASURED_ON`, `COMPARATOR` |

### 2.10 Stream: `runs.<shard_id>.jsonl` — `rec="RUN"`

Two record types discriminated by `phase`:

* `phase="OPEN"`: `{run_id, agent, shard, pid, boot_nonce, host, argv, git_commit, cwd, spec_version, ledger_schema, config_hash, started_ts}`
* `phase="CLOSE"`: `{run_id, ended_ts, status ∈ {OK,ERROR,ABORTED}, counts:{claims,status,edges,entities,mentions,events}, error?}`

A run with an `OPEN` and no `CLOSE` after `limits.run_stale_seconds` (default 86400) is reported by `mem doctor` as `ABANDONED`. It is never repaired by mutation; `mem run close --run-id ... --status ABORTED` appends a late `CLOSE`.

### 2.11 Stream: `events.<shard_id>.jsonl` — `rec="EVENT"`

The append-only operational event log. `event_type` ∈
`WRITE`, `DEDUPE`, `REJECT`, `READ`, `VERIFY_PASS`, `VERIFY_FAIL`, `REFUTE`, `SUPERSEDE`, `CONSOLIDATE`, `REBUILD`, `MIRROR`, `GC`, `REDACT`, `ERROR`, `DECAY_TICK`.
Plus `payload` (object, ≤ 8000 bytes serialized) and `severity` ∈ `INFO`, `WARN`, `ERROR`.

`READ` events carry `payload = {"query": <str>, "k": int, "hits": [<item_id>, ...], "latency_ms": float, "build_id": str}` — **one line per query, not one per hit.** Access statistics (§5.6, §6.1) are derived by aggregating these. This keeps usage data in the authoritative ledger rather than in the disposable index.

## 3. SQLite schema (`memory/index/derived.sqlite3`)

Opened with:

```sql
PRAGMA journal_mode = OFF;      -- derived; built into a temp file then atomically renamed
PRAGMA synchronous = OFF;
PRAGMA temp_store  = MEMORY;
PRAGMA cache_size  = -65536;    -- 64 MiB
PRAGMA foreign_keys = ON;
```

Durability is deliberately off: the database has no authority and is rebuilt in ~17 ms. Losing it costs nothing.

### 3.3 `conf_pct` — intra-agent confidence percentile

Because raw confidence is not commensurable across agents (a known risk), the builder computes, **per `agent_id`**, the empirical percentile of each claim's `confidence` among that agent's own claims:

```
conf_pct(d) = (rank_ascending_within_agent(confidence(d)) - 0.5) / n_claims(agent(d))
```
with ties assigned the average rank. Cross-agent ranking uses `conf_pct`, never `confidence`. `mem search --explain` prints both and labels raw confidence `intra-agent only`.

### 3.4 Status folding (exact algorithm)

```
for each item i:
    S = all status_record rows with target_id == i.id, gate_ok == 1
    order S ascending by (ts_ingest_ns, shard_id, seq)
    i.status        = S[-1].to_status  if S else 'ASSERTED'
    i.status_ns     = S[-1].ts_ingest_ns
    i.status_agent  = S[-1].agent_id
    i.superseded_by = last non-null superseded_by in S
    i.t_invalid_ns  = last non-null t_invalid_ns in S          # valid-time end
    i.status_contested = 1 if len({r.to_status for r in S}) > 1
                              and len({r.agent_id for r in S}) > 1 else 0
```

Rows with `gate_ok = 0` (the Voyager gate failed at rebuild time, e.g. the evidence edge is in a shard that has since been archived) are retained in `status_record` and reported by `mem doctor`, but do **not** affect the fold. Last-writer-wins is deliberate: a later `VERIFIED` after a `REFUTED` is a legitimate rebuttal in a critical-review MAS. `status_contested` makes the disagreement visible instead of hiding it, and `mem search` boosts contested items into view rather than burying them.

## 4. Bi-temporal model

Three distinct time axes are stored. Do not conflate them.

| axis | column(s) | meaning | who sets it | ordering authority |
|---|---|---|---|---|
| **decision time** | `ts_author_ns` | when the agent decided to write | the agent's clock | **none** — clocks are unsynchronized |
| **ingest time** | `ts_ingest_ns` | when the line hit the file | `time.time_ns()` inside `append()` | **total order** (with `shard_id`, `seq`) |
| **valid time** | `[t_valid_ns, t_invalid_ns)` | the interval over which the claim is asserted to be true of the world | the agent (`t_valid`), later a `STATUS` record (`t_invalid`) | domain semantics |

* `t_invalid_ns IS NULL` ⇒ the claim is still held to be valid. Half-open interval: `t_valid <= T < t_invalid`.
* **Nothing is ever deleted or edited to invalidate a claim.** Invalidation is a new `STATUS` line whose `t_invalid` closes the interval. This is Zep's invalidate-never-delete, and it is what makes "what did the ADMET team believe on 2026-07-01?" answerable.

### 4.1 Point-in-time queries

Every read path accepts two independent time filters:

```
--as-of <RFC3339>        # valid-time slice:  t_valid_ns <= AS_OF AND (t_invalid_ns IS NULL OR t_invalid_ns > AS_OF)
--known-as-of <RFC3339>  # ingest-time slice: ts_ingest_ns <= KNOWN_AS_OF, and status folding
                         #                    restricted to status_record.ts_ingest_ns <= KNOWN_AS_OF
```

Supplying both reconstructs "what we believed **then** about **then**" — the full bi-temporal rectangle. Default: `--as-of now`, `--known-as-of` unbounded.

Implementation note: `--known-as-of` requires re-folding status in SQL rather than reading the precomputed `item.status`. The builder therefore keeps every `status_record`; the query is:

```sql
WITH folded AS (
  SELECT target_id, to_status, t_invalid_ns,
         ROW_NUMBER() OVER (PARTITION BY target_id
                            ORDER BY ts_ingest_ns DESC, shard_id DESC, seq DESC) AS rn
    FROM status_record
   WHERE gate_ok = 1 AND ts_ingest_ns <= :known_as_of
)
SELECT i.*, COALESCE(f.to_status,'ASSERTED') AS status_at
  FROM item i LEFT JOIN folded f ON f.target_id = i.id AND f.rn = 1
 WHERE i.ts_ingest_ns <= :known_as_of;
```

### 4.2 Supersession

A correction is **never** an edit. `supersede()` appends, in this order, to three streams:

1. `claims.<shard>.jsonl` — the new, corrected CLAIM record (`id = clm_NEW`).
2. `edges.<shard>.jsonl` — `{"src":"clm_NEW","rel":"SUPERSEDES","dst":"clm_OLD"}`.
3. `status.<shard>.jsonl` — `{"target_id":"clm_OLD","to_status":"SUPERSEDED","superseded_by":"clm_NEW","t_invalid":<T>,"evidence_edge_id":"edg_...","reason":...}`.

`fsync` is issued after step 2 so the Voyager gate for step 3 is durably satisfiable. A crash between steps leaves a strictly weaker but consistent state (a new claim with no supersession, or a dangling `SUPERSEDES` edge), both detected by `mem doctor` and repairable by appending the missing record — never by editing.

## 5. The WRITE path

### 5.1 Chosen concurrency model: **per-shard single-writer append. No lock on the data path.**

**Decision.** 16 concurrent writers each own a distinct set of 7 files. Appends are ordinary `os.write` calls on an `O_APPEND` descriptor. There is no shared mutable resource on the write path, therefore no lock, no `busy_timeout`, no retry loop, and no contention.

**Justification against the alternative (shared SQLite in WAL mode):** measured on this machine, 16 writers × 500 records: **per-agent shards 8000/8000 lines, every line parsing, 131 ms**; shared SQLite WAL **8000/8000 but 710 ms (5.4×)**, and only because `busy_timeout` was set to 30 s — with a default or short timeout, writes fail under load and a naive implementation drops them silently. The shard design additionally (a) merges cleanly in git because concurrent agents touch disjoint files, (b) does not depend on `O_APPEND` write atomicity for correctness, since each file has exactly one writer, and (c) survives a crash with at worst one partial trailing line, which is deterministically detectable (§10 F-03). A single-writer queue was also rejected: it reintroduces a shared resource, a serialization point, and a process that can die while holding undelivered writes.

**Single-writer enforcement.** At `Ledger.__init__`, the process acquires `fcntl.flock(fd, LOCK_EX | LOCK_NB)` on `provenance/_locks/<agent_id>.lock`. Failure ⇒ raise `AgentLockHeld`, exit code 5. This prevents two processes from being launched with the same `agent_id` at all — even though the `pid`/`boot_nonce` suffix would already keep their *files* disjoint, sharing an `agent_id` would corrupt the `conf_pct` and consensus statistics.

### 5.2 File handling

```python
fd = os.open(path, os.O_WRONLY | os.O_CREAT | os.O_APPEND | os.O_CLOEXEC, 0o644)
```

* One `os.write(fd, data)` per record. `data` always ends with `b"\n"`. Records are capped at 65536 bytes.
* On open, the writer performs **tail repair**: seek to `max(0, size-65537)`, read to EOF; if the file is non-empty and does not end with `b"\n"`, `os.ftruncate(fd, last_newline_offset + 1)` and append an `EVENT{event_type:"ERROR", severity:"WARN", payload:{"repair":"truncated_tail", "bytes_dropped": n}}`. **Only the owning writer, under the agent lock, may repair. Readers never repair.**
* `fsync` policy from `config.durability.fsync` ∈ `always` | `batch` | `never`. Default `batch`: `os.fsync(fd)` when either 64 records or 2.0 s have elapsed since the last fsync, on every `verify`/`refute`/`supersede` edge write, and at `close()`. `always` costs ~2 ms/record on APFS; `never` is for benchmarks only.
* All 7 descriptors are opened lazily and closed in `Ledger.close()`, which also appends the `RUN` CLOSE record and fsyncs everything.

### 5.4 `append()` — the one internal write primitive

```python
def _append(self, stream: str, body: dict) -> WriteResult:
    # 1. envelope
    ts_ingest = time.time_ns()
    body |= {"rec": REC_OF[stream], "v": 1, "agent": self.agent_id,
             "shard": self.shard_id, "run_id": self.run_id,
             "seq": self._seq[stream], "ts_ingest": ts_ingest}
    body.setdefault("ts_author", rfc3339(ts_ingest))
    body["id"] = derive_id(stream, body)                 # §2.4

    # 2. validate  -> raises ValidationError (exit 2) on any violation
    schema.validate(stream, body)

    # 3. gate (STATUS only) -> raises GateError (exit 2)
    if stream == "status":
        gate.check(body, index=self._index_view, inflight=self._inflight)

    # 4. idempotency
    if body["id"] in self._written_ids[stream]:
        self.log("DEDUPE", {"stream": stream, "id": body["id"]})
        return WriteResult(body["id"], ..., deduped=True, byte_offset=-1, ...)

    # 5. serialize + single write
    data = (json.dumps(body, sort_keys=True, ensure_ascii=False,
                       allow_nan=False, separators=(",", ":")) + "\n").encode("utf-8")
    if len(data) > 65536:
        raise ValidationError("record exceeds 65536 bytes; move bulk text to episodic/")
    off = self._size[stream]
    n = os.write(self._fd[stream], data)
    assert n == len(data)                                # single writer: never partial
    self._size[stream] += n
    self._seq[stream]  += 1
    self._written_ids[stream].add(body["id"])
    self._inflight.record(stream, body)
    self._maybe_fsync(stream)
    return WriteResult(body["id"], body["id"][4:], False, stream, body["seq"], off, ts_ingest)
```

`self._written_ids` is seeded at open by scanning the shard's own existing files (cheap: the process owns them and they are small), so idempotency survives process restart within the same `shard_id` — and across `shard_id`s the id is different anyway only if `pid`/`nonce` entered the key, which they do not, so a restarted agent re-asserting the same claim still dedupes at the index level via `content_key`.

### 5.5 Write-time validation summary (all are exit code 2, all append a `REJECT` event)

1. JSON-schema conformance of every field (types, enums, ranges, regexes).
2. `source.ref` non-empty for citable source kinds.
3. Line size ≤ 65536 bytes.
4. No NaN/Infinity.
5. `tags` normalized, sorted, deduplicated, pattern-matched.
6. `span_end > span_start` and `span_end <= len(text_norm)` for mentions (the library resolves `text_norm` from the in-flight claim or the index).
7. **The Voyager gate** for `VERIFIED`/`REFUTED`/`SUPERSEDED` (§2.6).
8. `src != dst` for edges.
9. `target_id` / `src` / `dst` referencing a `clm_`/`ent_` id must resolve in the index or in-flight buffer *unless* the ref is an external token (`doi:`, `PMID:`, `CHEMBL:`, `NCT`, `http`), in which case it is recorded with `dst_resolved = 0`.

## 6. The READ path

### 6.1 Freshness: unconditional rebuild-on-change

Before **every** read operation:

```python
fp = fingerprint(root/"provenance")     # {relpath: (size, mtime_ns, inode)} for all *.jsonl
if fp != json.load(index/"manifest.json").get("files"):
    rebuild(root)                        # §6.2
```

Never incremental. The highest-severity failure this system can have is an agent missing a refutation because it read a stale index; unconditional rebuild removes that failure class entirely. Measured cost: 17 ms for 8000 records; budget holds to ~10⁵ records. Above `limits.rebuild_warn_items` (default 100000) `mem doctor` emits a WARN.

Rebuild is serialized by `flock` on `index/.rebuild.lock` (blocking, `timeout=15 s`). A process that fails to acquire it waits, then re-stats: if the manifest now matches, it proceeds against the freshly built DB; if not, it raises `IndexStale` (exit 4).

### 6.2 Rebuild procedure (deterministic, atomic)

1. `flock` `index/.rebuild.lock`.
2. `build_id = blake2b(concat of sorted (path, size, mtime_ns, sha256))[:16]`.
3. Create `index/derived.sqlite3.tmp.<pid>`, execute the DDL of §3.1.
4. Read every `provenance/*.jsonl`. For each file, stream lines with byte offsets. A final line lacking `\n` ⇒ record `ledger_error(kind='TRUNCATED_TAIL')` and stop that file (severity WARN — a live writer may be mid-append). **A non-terminal unparseable or schema-invalid line is a hard error:** record it in `ledger_error` and, unless `--tolerate-bad-lines` is passed, abort the rebuild with exit code 4 and print the path, line number, and prefix. Bad lines are never silently skipped.
5. Insert into `run`, `item`, `edge`, `status_record`, `entity`, `mention`, `event` in the total order `(ts_ingest, shard, seq)`, inside a single transaction. Assign `item.rowid_` densely, `1..N`, in that order.
6. Fold `status_record` into `item` (§3.4); mark `is_winner`; evaluate `gate_ok`.
7. Resolve `edge.src_resolved` / `dst_resolved` against `item.id` ∪ `entity.id`.
8. Apply redactions from `provenance/_redactions.jsonl` (§7.5): set `item.redacted=1`, replace `text`/`text_norm`.
9. Compute `conf_pct` (§3.3), `same_as_cluster` (union-find), `access_stat` (from `READ` events), `entity.mention_count`, `salience` (§7.1).
10. Populate FTS: `INSERT INTO item_fts(rowid, text, tags, claim_type, source_ref) SELECT rowid_, text, tags, claim_type, source_ref FROM item;` then `INSERT INTO item_fts(item_fts) VALUES('optimize');`
11. Build the vector matrix (§6.3.4) → `index/vectors.f32.tmp`, `vectors.meta.json.tmp`; fill `vector_slot`.
12. Write `meta` rows. `ANALYZE`. Close.
13. `os.replace()` each `.tmp` onto its final name (atomic within a filesystem). Write `manifest.json` **last**.
14. Release the lock; append a `REBUILD` event to the caller's ledger if a `Ledger` is open.

Determinism requirement: two rebuilds from identical ledger bytes MUST produce identical `build_id`, identical `item.rowid_` assignment, and byte-identical `vectors.f32`. A regression test asserts this.

### 6.3 The local vectorizer — **hashed character n-gram TF-IDF**

**This is a deterministic lexical-semantic approximation, not a neural embedding.** It captures morphological, orthographic, and lexical overlap — including robustness to typos, inflection, and chemical/gene identifier fragments — and it does **not** capture paraphrase or conceptual similarity between disjoint vocabularies. No model is downloaded; nothing but `hashlib` and `numpy` is used. Anywhere the system reports similarity, the label is `lexical-semantic (hashed 3–5-gram TF-IDF)`. It MUST NOT be described as a semantic embedding in output, docs, or the mirror.

#### 6.3.1 `normalize_text(s) -> str`

```python
s = unicodedata.normalize("NFKC", s)
s = s.casefold()
s = re.sub(r"[\u2010-\u2015\u2212]", "-", s)        # unify dashes
s = re.sub(r"\s+", " ", s).strip()
```

#### 6.3.2 Feature extraction

```python
D = 2048                      # config.vector.dim
CHAR_NS = (3, 4, 5)
MAX_CHARS = 4000              # deterministic truncation for char-grams

def features(text_norm: str) -> Counter[str]:
    f = Counter()
    for w in re.findall(r"[a-z0-9][a-z0-9+\-_.]*", text_norm):
        f["w:" + w] += 1
    body = " " + text_norm[:MAX_CHARS] + " "
    for n in CHAR_NS:
        for i in range(len(body) - n + 1):
            f[f"c{n}:" + body[i:i+n]] += 1
    return f
```

#### 6.3.3 Signed hashing and the document vector

```python
def bucket(feature: str) -> tuple[int, float]:
    h = int.from_bytes(hashlib.blake2b(feature.encode("utf-8"),
                                       digest_size=8, person=b"memvec1").digest(), "big")
    return h % D, (1.0 if (h >> 63) & 1 == 0 else -1.0)

def doc_vector(text: str) -> np.ndarray:            # float32, shape (D,)
    v = np.zeros(D, dtype=np.float32)
    for feat, tf in features(normalize_text(text)).items():
        idx, sgn = bucket(feat)
        v[idx] += np.float32(sgn * (1.0 + math.log(tf)))     # sublinear tf
    n = float(np.linalg.norm(v))
    return v if n == 0.0 else (v / np.float32(n))
```

The signed hash trick makes collision error zero-mean, so bucket collisions add variance rather than systematic bias.

**Document vectors carry no IDF.** They are therefore a pure function of the text — which is what makes the content-addressed cache always valid.

#### 6.3.4 IDF, applied on the query side only

Because the dot product is bilinear, weighting the query by per-bucket IDF is exactly equivalent to an IDF-weighted inner product:

```
idf[j] = log( (N - df[j] + 0.5) / (df[j] + 0.5) + 1.0 )      # BM25-style, always > 0
df[j]  = number of documents with v_d[j] != 0
```

`df` is computed once per rebuild over the assembled matrix (`(M != 0).sum(axis=0)`) and stored in `vectors.meta.json`.

```python
def query_vector(q: str, idf: np.ndarray) -> np.ndarray:
    v = doc_vector(q) * idf
    n = float(np.linalg.norm(v))
    return v if n == 0.0 else (v / np.float32(n))
```

#### 6.3.5 Storage, cache, and scan

* `index/vectors.f32`: raw C-order `float32` array, shape `(n_rows, D)`, no header. At N=10⁴, D=2048 this is **82 MB**. Loaded with `np.memmap` (or `np.fromfile` when `N*D*4 < config.vector.load_ram_bytes`, default 256 MB).
* `index/veccache.sqlite3`: `CREATE TABLE vec (content_key TEXT PRIMARY KEY, dim INTEGER NOT NULL, vec BLOB NOT NULL, last_used_ns INTEGER NOT NULL) WITHOUT ROWID;` — keyed by `blake2b16(normalize_text(text))`, so it is **never stale**; a rebuild is a memcpy for unchanged items. LRU-evicted by `mem gc` above `limits.veccache_mb` (default 512).
* `embedding_ref` on the CLAIM record is `f"h1:{D}:{blake2b(vec.tobytes(), digest_size=16).hexdigest()}"` — it lets a reviewer confirm from the ledger alone that the index was built from the same text.
* Search: `scores = M @ q` (numpy/BLAS, blocked, cache-friendly). Measured: 0.085 ms at 10⁴×384; ~0.5 ms at 10⁴×2048; 1.24 ms at 50k×768. **No ANN index. Recall of the vector channel is exactly 1.0 by construction**, which removes first-stage recall as a tunable variable entirely.

### 6.4 Stage A — candidate generation

**Lexical (FTS5 BM25).**

```sql
SELECT i.id, i.rowid_,
       bm25(item_fts, 1.0, 0.5, 0.25, 0.75) AS bm
  FROM item_fts
  JOIN item i ON i.rowid_ = item_fts.rowid
 WHERE item_fts MATCH :fts_query
   AND (:claim_type IS NULL OR i.claim_type = :claim_type)
   AND (:agent      IS NULL OR i.agent_id   = :agent)
   AND i.redacted = 0
   AND i.t_valid_ns <= :as_of
   AND (i.t_invalid_ns IS NULL OR i.t_invalid_ns > :as_of OR :include_invalid = 1)
 ORDER BY bm ASC
 LIMIT :n_lex;                              -- n_lex = 200
```

Column weights: `text 1.0, tags 0.5, claim_type 0.25, source_ref 0.75`. FTS5's `bm25()` returns a negated score, so **ascending** order is best-first. `:fts_query` is built by `fts_escape()`: split the user query on whitespace, wrap each token in double quotes with internal `"` doubled, join with `OR`; if the user passes `--raw-fts`, the string is used verbatim.

**Vector.**

```python
q = query_vector(query, idf)
s = M @ q                                          # (N,)
s[~mask] = -np.inf                                 # same SQL filters, as a boolean mask
top = np.argpartition(-s, n_vec)[:n_vec]           # n_vec = 200
top = top[np.argsort(-s[top], kind="stable")]
```

The mask is produced by one SQL query returning the allowed `rowid_` set, converted to a boolean array. `argpartition` keeps candidate selection O(N).

### 6.5 Stage B — Reciprocal Rank Fusion

```
RRF(d) = Σ_{c ∈ {lex, vec}}  w_c / (k + rank_c(d))
```

* **k = 60** (Cormack, Clarke & Buettcher, SIGIR 2009). Configurable as `search.rrf_k`; the default is the published convention, not a tuned value, and the implementation MUST NOT tune it silently.
* `rank_c(d)` is 1-based within channel `c`. If `d` is absent from channel `c`, that term is **omitted** (not treated as rank ∞ with a floor).
* `w_lex = 1.0`, `w_vec = 1.0` by default. RRF is used precisely because BM25 (unbounded, negated) and cosine (`[-1, 1]`) are not comparable in magnitude.

### 6.6 Stage C — priors

```
score_direct(d) = RRF(d) · ver(d) · rec(d) · imp(d) · acc(d)
```

**`ver(d)` — verification status multiplier** (`search.status_weights`):

| status | `default` profile | `audit` profile (`--profile audit`) |
|---|---|---|
| `VERIFIED` | 1.30 | 1.20 |
| `ASSERTED` | 1.00 | 1.00 |
| `REFUTED` | 0.90 | **1.35** |
| `SUPERSEDED` | 0.50 | 0.60 |

Additionally `× 1.15` when `status_contested = 1` in both profiles. Refuted claims are only mildly demoted, never hidden: in a critical-review MAS the record that a claim was refuted *is* the deliverable, and `--profile audit` promotes them to the top.

**`rec(d)` — recency**, bounded so it can never dominate:

```
rec(d) = 0.5 + 0.5 · exp( -ln2 · age_days(d) / H(memory_class(d)) )     ∈ (0.5, 1.0]
age_days(d) = (now_ns - d.ts_ingest_ns) / 86_400e9
H = {semantic: 180, episodic: 21, procedural: 3650, entity: 3650}       # half-lives, days
```

The 0.5 floor is deliberate: a rarely-mentioned but permanently true fact must never decay out of reach.

**`imp(d)` — self-reported importance**, mapped to a narrow band:

```
imp(d) = 0.7 + 0.6 · importance(d)                                      ∈ [0.7, 1.3]
```

**`acc(d)` — accessibility**, ACT-R base-level activation via Petrov's approximation over `access_stat`:

```
T_days = max(age_days(d), 1/1440)                 # floor at one minute
B(d)   = ln( n_access(d) + 1 ) / (1 - β)  -  β · ln(T_days),        β = 0.5
acc(d) = 0.50 + 0.75 · σ(B(d) - B0),    σ(x) = 1/(1+e^{-x}),  B0 = 0.0   ∈ (0.50, 1.25)
```

`acc` is **pinned to 1.25** when `memory_class = 'procedural'` or `'pin'` ∈ tags, and floored at 1.00 when `status = 'VERIFIED'`. **`acc` never causes deletion — it is a ranking multiplier only** (§8).

Note the deliberate absence of raw `confidence` from the ranking function. Cross-agent ranking on self-reported confidence is not sound. `conf_pct` is available as an *optional* tiebreaker via `--use-confidence`, which multiplies by `(0.9 + 0.2·conf_pct)` and prints a warning that the signal is intra-agent ordinal only.

### 6.7 Stage D — typed-edge graph expansion

Seeds = the top `n_seed = 25` items by `score_direct`. Expand up to `max_hops = 2` (3 for `mem trace`) over `edge`, in SQL, breadth-first:

```
γ = {SAME_AS: 0.95, SUPERSEDES: 0.90, REFUTES: 0.90, SUPPORTS: 0.80,
     CITES: 0.70, DERIVES_FROM: 0.60}          # relation decay
λ = 0.60                                        # per-hop decay

expanded(d) = max over (seed s, path p from s to d) of
                  score_direct(s) · λ^{|p|} · Π_{e ∈ p} ( γ(rel(e)) · weight(e) )

final(d) = max( score_direct(d), expanded(d) )
```

Traversal is undirected for `SAME_AS` and directed-with-reverse for the rest (both `src→dst` and `dst→src` are followed, since "what refutes X" and "what does X refute" are both wanted); the relation decay is identical in either direction. Each result carries `via` — either `"direct"` or the explicit path `"clm_a --REFUTES--> clm_b --CITES--> PMID:38112233"` — so every hit is explainable.

### 6.8 Stage E — `SAME_AS` collapse

Results are grouped by `same_as_cluster.cluster_id`. Each cluster contributes **one** row, the highest-scoring member, annotated with `cluster_size` and `distinct_agents`. **Any consensus statement MUST be computed over `distinct_agents` of the collapsed component, never over raw row counts.** `mem consensus` refuses to report a count without also printing `distinct_agents`, and `mem search --json` always emits both.

### 6.9 Stage F — output and the read event

Return the top `k` (default 10). Then append **exactly one** `READ` event to the ledger with the query, `k`, the returned ids, latency, and `build_id`. This is what feeds `access_stat` on the next rebuild.

### 6.10 The multi-hop reference query (regression test — MUST return non-empty)

Refuted ADMET claims, with their refuting evidence and the citing DOI/PMID. Measured at **0.09 ms**.

```sql
-- tests/test_multihop.py::test_admet_refutation_chain
SELECT  c.id            AS refuted_claim_id,
        c.agent_id      AS claimant,
        c.text          AS refuted_claim,
        c.t_invalid_ns  AS invalidated_at,
        r.id            AS refuter_id,
        r.agent_id      AS challenger,
        r.text          AS refuting_claim,
        e2.dst          AS citation,
        s.reason        AS refutation_reason
  FROM item  c
  JOIN edge  e1 ON e1.dst = c.id  AND e1.rel = 'REFUTES'      -- hop 1
  JOIN item  r  ON r.id   = e1.src
  JOIN edge  e2 ON e2.src = r.id  AND e2.rel = 'CITES'        -- hop 2
  LEFT JOIN status_record s ON s.evidence_edge_id = e1.id AND s.is_winner = 1
 WHERE c.claim_type = 'ADMET'
   AND c.status     = 'REFUTED'
 ORDER BY c.t_invalid_ns DESC;
```

The third hop (`c` ← `e1` → `r` → `e2` → citation) needs no graph engine and no entity extraction, because the edges are *born structured*: the verification agent that refutes a claim writes the `REFUTES` and `CITES` edges at that moment. Inference machinery would only add an error term.

## 7. The CONSOLIDATION path (sleep-time compute)

### 7.1 Salience score (computed every rebuild, stored in `salience`)

All six components are in `[0,1]`, weights sum to 1.

```
U (usage)        = 1 - exp( -n_access(d) / 5 )
C (connectivity) = 1 - exp( -(deg_in(d) + deg_out(d)) / 4 )
V (verification) = {VERIFIED: 1.0, REFUTED: 0.8, ASSERTED: 0.4, SUPERSEDED: 0.1}[status(d)]
I (importance)   = 0.5·importance(d) + 0.5·conf_pct(d)          # intra-agent normalized
R (redundancy)   = m / (m + 2),  m = cluster_size(d) - 1
A (age)          = 1 - exp( -age_days(d) / 30 )

salience(d) = 0.25·U + 0.20·C + 0.25·V + 0.15·I + 0.10·R + 0.05·A     ∈ [0, 1]
```

`REFUTED` scores 0.8 on V — a well-evidenced refutation is high-value memory, not garbage. `R` rewards redundancy *for summarization*, which is the opposite of counting it as corroboration.

### 7.2 When consolidation runs

* On explicit `mem consolidate`.
* Automatically when a `Ledger` closes and `time_since_last_consolidation > consolidation.min_interval_s` (default 3600) **and** the process is not under an interactive TTY, i.e. genuinely idle.
* Recommended production trigger: a `launchd` `StartCalendarInterval` job on the user's machine running `mem consolidate --budget 120`.

Consolidation is **interruptible and idempotent**: it only ever appends, its outputs are content-keyed, and re-running it produces `deduped=True` for work already done. A `SIGTERM` mid-pass leaves a strictly-consistent shorter ledger.

### 7.3 What consolidation is permitted to do

Consolidation runs as agent `agent_id = "consolidator"` with its own shard, and is permitted **exactly three** operations:

1. **Append `SAME_AS` edges.** For every pair `(a, b)` of claims with the same `claim_type`, from different agents, with
   `cos(v_a, v_b) >= consolidation.same_as_tau` (default **0.86**) **and** Jaccard overlap of word-unigram sets `>= 0.55` **and** either sharing a mentioned `entity_id` or sharing a `source_ref` — append `SAME_AS`. The dual lexical criterion exists because the vectorizer is a lexical approximation; a single cosine threshold would over-merge. Candidate pairs come from a blocked `M @ M.T` over the ≤ 5000 highest-salience open claims (100 MB, ~0.4 s), never over the whole corpus.
2. **Append `SUPERSEDES` edges + `STATUS`** only when an explicit, checkable numeric contradiction is found: same `entity_id`, same `claim_type`, same extracted metric name, and non-overlapping numeric intervals parsed by a strict regex (`(IC50|EC50|Ki|Kd|CL|t1/2|AUC|Cmax)\s*[=<>~]+\s*([\d.]+)\s*(nM|uM|µM|mM|h|L/h)`). If the regex does not match, consolidation does nothing. It never uses judgment.
3. **Append `SUMMARY` claims.** For every `SAME_AS` cluster with `cluster_size >= 3` and `mean(salience) >= consolidation.tau_promote` (default **0.62**), append one CLAIM with `claim_type='META'`, `memory_class='semantic'`, `tags=['consolidated','summary']`, text = the highest-salience member's text verbatim plus a deterministic suffix listing member ids and `distinct_agents`, `source = {kind:'agent_inference', ref:''}`, `confidence = min over members of confidence`, and a `DERIVES_FROM` edge to every member. Summaries are ordinary claims and are themselves subject to refutation.

**Consolidation MUST NOT:** delete anything, rewrite anything, change any claim's text, set `VERIFIED`, or emit `REFUTES`.

Every pass appends one `CONSOLIDATE` event with counts and the `build_id` it operated on, so an offline error is traceable to a specific input state.

### 7.4 Compression of episodic traces

Episodic trace files older than `consolidation.episodic_compact_days` (default 30) are gzip-compressed in place (`x.trace.jsonl` → `x.trace.jsonl.gz`, original removed **only after** the `.gz` is fsynced and its SHA-256 recorded in a `GC` event). Compression is content-preserving; `episodic_ref` resolution transparently tries both extensions. This is the only automatic transformation applied to episodic files.

## 8. The FORGETTING path

### 8.1 Never deleted, never rewritten (hard invariant)

Everything under `memory/provenance/` — every CLAIM, STATUS, EDGE, ENTITY, MENTION, RUN, and EVENT record, including refuted claims, superseded claims, failed verifications, and rejected writes. There is no code path in `mem/` that opens a `provenance/*.jsonl` file for writing without `O_APPEND`, and `mem doctor` asserts this by checking that every committed file's git history is append-only (`git log -p` shows no deletions) when run inside a repo.

### 8.2 What decays (ranking only, never storage)

`acc(d)` (§6.6). Items that are never retrieved sink; items that are retrieved rise. The floor of 0.50 means a decayed item is at worst 2.5× down-weighted relative to a hot one — it remains findable by an exact-match query. Type exemptions: `procedural` and pinned items are exempt; `VERIFIED` items have a floor of 1.00.

### 8.3 What is genuinely reclaimable

| target | policy | command |
|---|---|---|
| `memory/index/**` | fully disposable, rebuilt in ~17 ms | `mem rebuild --force`, or just `rm -rf memory/index` |
| `veccache.sqlite3` | LRU eviction above 512 MB | `mem gc` |
| episodic traces > 30 d | gzip compaction (§7.4) | `mem gc` |
| episodic traces > `forget.episodic_purge_days` (default **0** = never) | hard delete, requires `--purge` **and** `--yes`; appends a `GC` event listing every deleted path with its SHA-256 (a tombstone) | `mem gc --purge --older-than 365d --yes` |
| `provenance/**` | **never** | — |

### 8.4 Preventing git bloat

Bulk reasoning transcripts MUST go to `memory/episodic/`, referenced from claims by `episodic_ref`. The 65536-byte record cap makes the alternative physically impossible. `mem doctor` WARNs when the mean claim line length exceeds 2 KB or when `provenance/` exceeds `limits.provenance_warn_mb` (default 64 MB). Target: 10⁴ claims ≈ 5 MB, fully reviewable in a PR.

### 8.5 Redaction (the one narrow escape hatch)

For legal erasure only, not for ordinary correction.

* `mem redact --id clm_... --reason "<text>"` appends one line to `provenance/_redactions.jsonl`. The original ledger line is untouched. The rebuild replaces `item.text`/`text_norm` with `[REDACTED:<reason>]`, sets `redacted=1`, excludes the item from FTS and from the vector matrix, and the mirror renders a redaction stub. This is the default and it preserves the audit trail completely.
* `mem redact --id ... --hard --yes` additionally overwrites the original line's bytes in place with `{"rec":"TOMBSTONE","v":1,"id":"<same id>","reason":"...","filler":"XXXX…"}` padded with a `filler` string to the **exact original byte length**, so no offsets shift, then appends a `REDACT` event. **This is the only permitted rewrite of a ledger file in the entire system.** It requires the agent lock on the owning shard, refuses to run while any other `mem` process holds a lock, forces a full rebuild, and prints the git command the operator must run. It is not reachable from the Python API — CLI only, with `--yes`.

## 9. The human-readable mirror

### 9.1 Status: **generated view, not source of truth**

`memory/semantic/**.md` is a deterministic, byte-stable rendering of the index. The ledger JSONL remains authoritative; the markdown exists so a human reviewing a PR sees prose rather than JSON. Both are committed: JSONL gives line-precise provenance diffs, markdown gives readability.

**Editing a mirror file by hand has no effect on system state and will be overwritten.** Every generated file begins with:

```markdown
<!-- GENERATED BY `mem mirror` FROM build_id=<...> AT <RFC3339>. DO NOT EDIT.
     Source of truth: memory/provenance/*.jsonl -->
```

`memory/procedural/**.md`, by contrast, **is** authoritative and is never generated or touched by `mem mirror`.

### 9.2 Files produced

| file | content |
|---|---|
| `semantic/index.md` | counts by agent / status / claim_type; top 50 by salience; links to the rest |
| `semantic/disputes.md` | every row of `v_dispute`, grouped by refuted claim: the claim, the challenger, the refuting claim, the citation, the reason. **This is the primary review artifact of a critical-review MAS.** |
| `semantic/timeline.md` | all status transitions in ingest order, one line each: `2026-08-16T12:34:56Z  admet-critic  REFUTED  clm_7b1f…  "CYP3A4 IC50 < 1 uM"  ← PMID:38112233` |
| `semantic/claims/<agent_id>.md` | that agent's claims, newest first, with status badge, source, confidence (labelled *intra-agent*), tags, and `SAME_AS` cluster size |
| `semantic/entities/<slug>.md` | canonical name, xrefs, aliases, and every claim mentioning it, grouped by role and status |

### 9.3 Determinism and sync enforcement

* Rows sorted by explicit total order (never by dict iteration). Timestamps rendered UTC RFC3339 seconds precision. Floats formatted `f"{x:.3f}"`. Trailing newline, LF only, no trailing spaces.
* `mem mirror --check` regenerates into a temp dir and byte-compares. Drift ⇒ **exit code 3** and a diff summary.
* Recommended `.git/hooks/pre-commit`:
  ```sh
  #!/bin/sh
  memory/bin/mem mirror --check || { echo "run: memory/bin/mem mirror"; exit 1; }
  ```
* CI equivalent: `mem rebuild --force && mem mirror --check && mem doctor --strict`.

The mirror is therefore *provably* in sync with the ledger at every commit, and the sync direction is unambiguously one-way.

## 11. Failure modes

| id | failure | detection | handling |
|---|---|---|---|
| **F-01** | Two processes launched with the same `agent_id` | `flock` on `_locks/<agent_id>.lock` at `Ledger.__init__` | `AgentLockHeld`, exit 5, nothing written. Even if the lock were bypassed, `pid`+`boot_nonce` keep the files disjoint. |
| **F-02** | Agent restarted while the old process still holds descriptors | new `pid`/`boot_nonce` ⇒ new `shard_id` ⇒ new files | no interleaving is physically possible |
| **F-03** | Crash mid-`write` leaves a partial trailing line | reader: last line has no `\n`; writer: same, at open | Reader records `TRUNCATED_TAIL` (WARN) and ignores it — a live writer may simply be mid-append. Only the owning writer, under the lock, truncates back to the last `\n` and logs the repair. **A non-terminal unparseable line is a hard error (exit 4), never skipped.** |
| **F-04** | **Agent reads a stale index and misses a refutation** — the highest-severity failure | `manifest.json` fingerprint (size, mtime_ns, inode) of every provenance file, checked on every read | unconditional full rebuild (~17 ms). Never incremental. Above 10⁵ items `doctor` WARNs that the budget is being exceeded. |
| **F-05** | Agents write claims but skip edges ⇒ R3 degrades to grep quality | `mem doctor` reports `refuted_without_edge`, `verified_without_edge`, `edges_per_claim` per agent; CI threshold `doctor.min_edges_per_refutation = 1.0` | The Voyager gate makes it structurally impossible for `REFUTED`/`VERIFIED`/`SUPERSEDED` to exist without an edge and a source ref: `set_status` hard-rejects (exit 2). The residual risk — a claim that *should* have been refuted but nobody wrote anything — is a protocol problem, surfaced as a per-agent metric, not a storage problem. |
| **F-06** | Semantic duplicates inflate apparent consensus | `same_as_cluster.distinct_agents` vs `cluster_size` | `mem search` collapses clusters by default; `mem consensus` refuses to emit a count without `distinct_agents`; `v_consensus` is the only sanctioned aggregation surface. Raw `COUNT(*)` over `item` is documented as **wrong** for consensus. |
| **F-07** | **The contentless-FTS5 trap** — `content=''` makes the FTS table return zero rows when joined to `item`, so the multi-hop query silently returns nothing instead of erroring | it does not error; only a fixture test catches it | The DDL mandates **external content** (`content='item'`, `content_rowid='rowid_'`). Regression test `tests/test_multihop.py::test_admet_refutation_chain` asserts the §6.10 query returns ≥ 1 row on the shipped fixture, and `tests/test_fts.py::test_fts_join_nonempty` asserts `SELECT count(*) FROM item_fts JOIN item ... > 0`. Both run in CI. |
| **F-08** | Non-deterministic serialization destroys diffability | `mem fsck` re-serializes every record from its parsed form and byte-compares against the file | mismatch ⇒ exit 4. `json.dumps(sort_keys=True, ensure_ascii=False, allow_nan=False, separators=(",",":"))` is centralized in one function; a lint test asserts no other `json.dumps` call site exists in `mem/`. |
| **F-09** | Episodic traces leak into the claim ledger, bloating git | 65536-byte record cap; `doctor` WARNs on mean line length > 2 KB or `provenance/` > 64 MB | oversize write is rejected (exit 2) with the message "move bulk text to episodic/ and reference it via episodic_ref" |
| **F-10** | Dangling edge (`src`/`dst` unresolvable) | `edge.src_resolved` / `dst_resolved` set at rebuild; `doctor` lists them | WARN, not an error: an edge may legitimately point at an external `PMID:`/`DOI:` token, or at a claim in a shard not yet flushed. `doctor --strict` fails only for dangling `clm_`-prefixed refs. |
| **F-11** | Conflicting statuses from two agents | fold detects `status_contested` | Last-writer-wins in total order (a later `VERIFIED` after a `REFUTED` is a legitimate rebuttal), **plus** `status_contested = 1`, a `× 1.15` search boost, a row in `v_dispute`, and a section in `semantic/disputes.md`. Disagreement is surfaced, never resolved silently. |
| **F-12** | Clock skew between agents | `ts_author` may go backwards relative to `ts_ingest` | Ordering uses `ts_ingest` exclusively. `doctor` WARNs when `abs(ts_author - ts_ingest) > 300 s`. |
| **F-13** | Rebuild races with a concurrent rebuild | `flock` on `index/.rebuild.lock` | second process blocks up to 15 s, then re-stats; if the manifest now matches it proceeds, else exit 4 |
| **F-14** | Rebuild crashes halfway | build goes to `*.tmp.<pid>`, `os.replace` last, `manifest.json` written last | a half-built DB is never observable; the old index remains valid, and the next read re-triggers the rebuild |
| **F-15** | Corpus grows beyond the brute-force budget | `doctor` WARNs above `limits.rebuild_warn_items` (10⁵) | The documented next move is **Matryoshka prefix scan + full-dimension rescoring, or int8/RaBitQ with fp32 rescoring — not an HNSW graph.** (Brute force measured at 1.24 ms for 50k×768; an ANN index could save at most ~0.08 ms at spec scale.) |
| **F-16** | Confidence used for cross-agent ranking | `--use-confidence` prints a warning; raw `confidence` is absent from the default scoring function | ranking uses `conf_pct` (intra-agent percentile) only, and cross-agent weight is carried by `VERIFIED`/`REFUTED` status, which is backed by an edge and a source |
| **F-17** | Consolidation writes a wrong `SAME_AS`/`SUPERSEDES` offline and it is hard to trace | every pass appends a `CONSOLIDATE` event with the `build_id`, thresholds, and every edge id emitted | consolidation only ever appends; a wrong `SAME_AS` is corrected by a human appending a `REFUTES` on the merge or by raising `same_as_tau` and re-running — the bad edge stays visible in the ledger, as designed |
| **F-18** | Markdown mirror hand-edited | `mem mirror --check` byte-compare | exit 3, pre-commit hook blocks the commit; the DO-NOT-EDIT banner states the mirror is generated |
| **F-19** | Disk full mid-write | `os.write` raises `ENOSPC` | the partial line is repaired on next open (F-03); the `Ledger` closes with `status=ERROR`; exit 4 |
| **F-20** | `veccache` grows unbounded | `mem gc` LRU-evicts above `limits.veccache_mb` | the cache is content-addressed and therefore always safe to delete entirely |
